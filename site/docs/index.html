01 / Plan

Before you start

The dashboard can run anywhere that can reach your Project Zomboid RCON port. Optional features also need read access to files exposed by your game host.

Required

  • A Docker host or Node.js 22+ machine.
  • Your Project Zomboid server's RCON hostname or IP, RCON port, and RCON password.
  • A persistent directory or Docker volume for encrypted configuration and dashboard data.
  • A strong dashboard administrator password of at least 16 characters.

Optional

  • FTP or FTPS credentials for deep telemetry, Project Zomboid account sign-in, or remote server files.
  • The separate PZ RCON Admin Telemetry companion on Steam Workshop.
  • An HTTPS reverse proxy for access beyond a trusted local network.
  • Optional read-only local mounts for servertest.ini and servertest_SandboxVars.lua when FTP is unavailable.
Do not expose RCON to the public internet.

The dashboard needs to reach RCON, but browsers do not. Restrict the RCON port to the game host, dashboard host, or private network.

02 / Deploy

Docker quick start

This Compose file uses the published GHCR image and stores encrypted settings, player history, roles, requests, and audit data in a named volume.

compose.yaml
name: pz-rcon-admin

services:
  dashboard:
    image: ghcr.io/doomedgaming/pz-rcon-admin:latest
    container_name: pz-rcon-admin
    restart: unless-stopped
    init: true
    read_only: true
    cap_drop:
      - ALL
    security_opt:
      - no-new-privileges:true
    ports:
      - "127.0.0.1:8788:8787"
    volumes:
      - pz-rcon-admin-data:/app/data
    tmpfs:
      - /tmp:size=16m,mode=1777

volumes:
  pz-rcon-admin-data:

The example binds to loopback for a reverse proxy on the same machine. For trusted LAN access, replace 127.0.0.1 with the dashboard host's LAN address, such as 10.10.10.25. Use 0.0.0.0 only when the host firewall restricts access appropriately.

Start and read the one-time setup URL
docker compose pull
docker compose up -d
docker compose logs -f dashboard

Open the one-time /setup?token=… URL printed in the logs. If the container runs on another machine, replace the URL's host with the LAN hostname, IP, or reverse-proxy hostname while preserving the full path and token.

No environment file is required.

The setup page stores secrets in an encrypted server-side configuration. A named volume preserves the ciphertext and its key when the container is recreated.

03 / Connect

First-run setup

The setup URL is single-use. Secrets are encrypted when saved and are never returned to the browser afterward.

Dashboard security

FieldWhat to enter
Administrator passwordA unique password of 16 or more characters. This is the bootstrap and break-glass admin login; it is not the RCON password.
Session signing secretLeave blank to generate a strong random value, or provide at least 32 random characters.
Dashboard is served through HTTPSEnable only when users reach the dashboard through an HTTPS reverse proxy. This turns on secure-only session cookies.

Project Zomboid RCON

FieldWhat to enter
RCON hostThe hostname or IP reachable from inside the container. Do not use 127.0.0.1 unless the game server is in the same container.
RCON portThe server's configured RCON port—not the Project Zomboid gameplay port and not the dashboard's web port.
RCON passwordThe value configured as RCONPassword for the Project Zomboid server.

Optional sections

Server-file access, player account sign-in, branding, public links, restart schedule, announcement, and provider URL can all be left blank and added later from Admin → Configuration.

What happens after save

  1. The dashboard validates the merged configuration.
  2. Secrets and non-secret settings are encrypted atomically in the persistent data volume.
  3. The process exits intentionally.
  4. Docker's restart: unless-stopped policy starts it with the saved configuration.
  5. The setup page reconnects and opens /admin.
Where the data lives

The container stores the encrypted configuration under /app/data/secure-config and dashboard state at /app/data/dashboard.json. Both live in the volume from the Compose example.

Staff and break-glass routes

Routine Moderator and Admin sessions enter through /mod. The player portal links only to that shared staff route. The unlinked /admin route is reserved for the bootstrap administrator password, and staff logout returns to the player portal instead of revealing its form.

04 / Publish safely

Reverse proxy

Keep the container bound to loopback when the reverse proxy runs on the same host. Terminate HTTPS at the proxy and forward normal HTTP to port 8788.

Caddy

Caddyfile
pz-admin.example.com {
  reverse_proxy 127.0.0.1:8788
}

Nginx

Server block
server {
  listen 443 ssl;
  server_name pz-admin.example.com;

  location / {
    proxy_pass http://127.0.0.1:8788;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
Turn on secure cookies after HTTPS works.

Open Admin → Configuration, enable Dashboard is served through HTTPS, and save. The container restarts automatically. Enabling it before HTTPS is available prevents browsers from sending the login cookie over HTTP.

05 / Optional signal

Deep telemetry

Vanilla RCON does not expose character health, skills, traits, position, current powers, server role definitions, or vehicle key IDs. Install one telemetry package to add that data and enable acknowledged live SandboxVars control.

Option A

Steam Workshop

Add Workshop item 3767189432 and Mod ID PZRconAdminTelemetry to the server, then restart. This variant synchronizes SandboxVars changes to connected clients.

Option B

Direct install

Download the Lua asset from the latest telemetry release and upload it to media/lua/server/PZRconAdminTelemetry_Server.lua. It applies server changes, but client-cached settings may require reconnecting.

Install only one variant.

Do not enable the Workshop mod while the direct-install Lua file is present. Game updates or “Verify game files” may remove the direct-install file, so check it after either operation.

Connect the dashboard

In first-run setup or Admin → Configuration, enter the FTP or FTPS credentials supplied by the game host:

FieldDefault / meaning
FTP/FTPS host, port, username, passwordThe file-service credentials from the hosting provider. Sandbox live needs permission to create and update files beside the telemetry snapshot.
TransportPlain FTP, explicit FTPS, or implicit FTPS according to the provider.
Telemetry file pathLua/PZRconAdminTelemetry/players.txt (JSON content)
Server INI FTP pathServer/servertest.ini
SandboxVars FTP pathServer/servertest_SandboxVars.lua
Telemetry poll interval5 seconds by default. Configuration files refresh separately every 60 seconds by default.
Telemetry HTTP tokenLeave blank unless a custom sender will post authenticated snapshots to the HTTP receiver.

The Lua exporter writes at most every 5 seconds during steady activity, with extra event-driven writes at startup and when the online-player count changes. The dashboard retrieves the latest snapshot on the same interval.

Change SandboxVars without restarting

Open Admin → Sandbox live, search the options loaded from the server's SandboxVars file, change one typed value, and apply it. The backend writes a request beside the telemetry snapshot; Project Zomboid validates, applies, and saves the option before the companion acknowledges success. The Workshop variant also synchronizes connected clients.

Live does not mean retroactive.

World-generation and initial-character options are saved for future use but cannot rebuild existing cells or existing characters. Map and Workshop lists are not editable through this page.

06 / Optional access

Player account sign-in

When enabled, survivors can use their personal Project Zomboid username and password to open their private player portal. This is not the shared server password.

  1. Enable Player account sign-in.
  2. Leave the separate FTP fields blank to reuse telemetry credentials, or enter a dedicated read-only file account.
  3. Keep the account database path at db/servertest.db unless the provider exposes a different remote root.
  4. Keep the world name at servertest unless the server uses a different world/database name.
  5. Leave the player session secret blank to generate it, or provide a distinct 32+ character random value.

The backend downloads the account database into a private temporary directory, verifies the Build 42 password representation, and immediately removes the copy. The database and password hashes are never returned to the browser or written to dashboard history.

Plain FTP is not encrypted.

If the provider offers only FTP, account database hashes cross that connection without transport encryption. Keep the connection on a trusted/private network or leave player sign-in disabled unless you accept that risk.

07 / Optional context

Server config files

The dashboard automatically retrieves servertest.ini and SandboxVars.lua through the configured FTP or FTPS account. It checks them at startup and on every FTP poll, updating maps, mods, and searchable settings without a dashboard restart.

G-Portal exposes the defaults as Server/servertest.ini and Server/servertest_SandboxVars.lua. Change the remote paths in setup only when a provider uses a different FTP root or world name.

If FTP is unavailable, Docker can instead use protected local copies. Add read-only mounts and enter the container paths in setup; local files override FTP retrieval:

Additional Compose volume mounts
services:
  dashboard:
    volumes:
      - pz-rcon-admin-data:/app/data
      - /host/path/servertest.ini:/config/servertest.ini:ro
      - /host/path/servertest_SandboxVars.lua:/config/servertest_SandboxVars.lua:ro
Setup fieldContainer path
servertest.ini path/config/servertest.ini
SandboxVars.lua path/config/servertest_SandboxVars.lua

The imported INI and SandboxVars source files remain read-only dashboard context. When FTP telemetry control is configured, Sandbox live asks Project Zomboid itself to apply and save one validated option through separate Lua/PZRconAdminTelemetry/control.txt and control-status.txt files. Read-only local mounts cannot enable that control path.

08 / Reconfigure

Change settings later

Admins can open Configuration in the control console to correct RCON, telemetry, file access, player sign-in, and community settings.

  • Non-secret values load into the form.
  • Stored secrets appear only as configured/not-configured indicators.
  • Leave a secret field blank to keep it.
  • Enter a new value to replace it, or use an explicit remove/rotate control where offered.
  • Saving exits the process after the encrypted write; Docker restarts it automatically.
Environment overrides win.

If a setting is supplied to the container as an environment variable, change it in the deployment configuration. The in-app form cannot override the running process environment.

Moderation accountability.

Kick, ban, and whitelist removal stay disabled until staff enter a reason. The API also rejects blank reasons, and successful actions retain the reason in the administrator audit log.

09 / Maintain

Updates and backups

Update the dashboard

Pull the latest image
docker compose pull dashboard
docker compose up -d --no-build dashboard
docker compose logs --tail=100 dashboard

For predictable rollouts, replace latest in Compose with a release such as 0.7.5. The tags X.Y.Z and X.Y are published for each release.

Back up persistent data

Back up the named volume before major changes. It contains both the encrypted configuration and the encryption key, plus player history, roles, support requests, preferences, and audit records. A backup of only one secure-config file is not sufficient.

Update telemetry

The admin app and telemetry companion use matching release versions. Update the Workshop item normally, or replace the direct-install Lua file with the asset from the matching telemetry release. Restart the Project Zomboid server after changing the telemetry package.

10 / Recover

Troubleshooting

Container is unhealthy

Inspect health and logs
docker compose ps
docker compose logs --tail=200 dashboard
curl -i http://127.0.0.1:8788/api/health

During first-run setup, use the current image and keep the persistent volume writable at /app/data. If setup saved successfully but the service did not return, confirm restart: unless-stopped is present and restart the service once.

RCON will not connect

  • Confirm the RCON host is reachable from inside the container.
  • Confirm the port is the RCON port, not the gameplay port.
  • Verify the server's RCON password and firewall rules.
  • Remember that localhost inside the container refers to the container itself.

Telemetry shows no players

  • Install exactly one telemetry variant and restart the game server.
  • Join the server and verify Lua/PZRconAdminTelemetry/players.txt exists and is updating.
  • Confirm the FTP remote path uses forward slashes and the provider's remote root.
  • Check the Mods & Settings integration status for the most recent FTP error.
  • After a game update or file verification, confirm the direct-install Lua file still exists.

Login loops behind HTTPS

Confirm the proxy sends X-Forwarded-Proto: https, the public URL is really HTTPS, and secure cookies are enabled. Clear stale cookies after changing between HTTP and HTTPS.

12 / Harden

Security checklist

  • Use unique dashboard, RCON, FTP, and session secrets.
  • Keep RCON and file-service ports off the public internet.
  • Use HTTPS and secure cookies for any access outside a trusted LAN.
  • Prefer FTPS or a private network; plain FTP exposes traffic in transit.
  • Keep the persistent data volume readable only by the container host administrator.
  • Back up the entire volume because the encrypted store and master key are both required.
  • Promote Project Zomboid accounts to Moderator or Admin explicitly; every account begins as User.
  • Review the audit log and update to current matching admin/telemetry releases.
